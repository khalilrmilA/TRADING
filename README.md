A self-hosted research workbench that combines classic technical analysis, rule-based
strategies, an event-driven backtester, a risk-managed **paper** trading engine, and a
local LLM analyst (via [Ollama](https://ollama.com)) behind a FastAPI backend and a
Streamlit dashboard.

---

## Features

- **Market data** — public OHLCV from **Binance**, **Bybit** (spot) and **Yahoo Finance**;
  incremental caching into SQLite (WAL), background auto-refresh every 15 minutes.
- **Indicators** — pure pandas/numpy implementations (no TA-Lib): SMA, EMA, RSI (Wilder),
  MACD, Bollinger Bands, ATR, VWAP, volume profile, returns, volatility, momentum.
  Strict no-lookahead guarantees.
- **AI analyst** — local LLM (qwen3 / deepseek-r1 via Ollama) turns an indicator snapshot
  into structured JSON: sentiment, confidence, key indicators, risk commentary, reasoning.
  Automatic retries, model fallback, `<think>` stripping, JSON repair pass.
- **Strategies** — trend following, mean reversion, breakout, RSI+MACD, and a majority-vote
  **ensemble**; all signal-based with next-bar-open execution semantics.
- **Backtester** — bar-by-bar engine with slippage, commissions, ATR position sizing,
  ATR stop-loss/take-profit, intrabar stop checks, full metrics suite
  (Sharpe, Sortino, CAGR, max drawdown, profit factor, exposure, ...), plus
  **walk-forward** evaluation.
- **Paper trading** — persistent simulated account (SQLite): market/limit/stop orders,
  auto position sizing, SL/TP, mark-to-market equity snapshots, and hard risk rules
  (max positions, daily loss limit, drawdown circuit breaker).
- **Dashboard** — Streamlit + Plotly: candlesticks with overlays, AI analysis panel,
  backtest lab, paper-trading cockpit, strategy comparison.
- **Ops** — one-click Windows `.bat` scripts, Docker Compose (backend + dashboard,
  Ollama stays on the host GPU), everything configurable via `.env`.

## Hardware & model guide

This platform was tuned on: **NVIDIA RTX 5060 Ti (16 GB VRAM) + 32 GB RAM, Windows 11**.
Rule of thumb: a model runs **fast** when its weights + KV cache fit entirely in VRAM;
once it spills to system RAM (CPU offload), token speed drops roughly 5–10x.

| Model               | Approx. size | On a 16 GB GPU              | Typical speed  | Best for                                |
|---------------------|--------------|-----------------------------|----------------|-----------------------------------------|
| **`qwen3:14b`** ⭐ default | ~9.3 GB  | **Fully in VRAM**           | Fast (interactive) | Everyday market analysis — best speed/quality balance |
| `qwen3:30b-a3b`     | ~19 GB (MoE, 3B active) | Partial offload, but only ~3B params active per token | Surprisingly fast | **Quality upgrade** without the dense-32B slowdown |
| `qwen3:32b`         | ~20 GB       | CPU offload                 | ~5–10 tok/s    | Max quality when you can wait            |
| `deepseek-r1:32b`   | ~20 GB       | CPU offload                 | ~5–10 tok/s    | Deep step-by-step reasoning (configured fallback) |
| `qwen2.5-coder:32b` | ~20 GB       | CPU offload                 | ~5–10 tok/s    | Code generation (configured code model)  |

The 32B dense models **work** on this hardware — they are configured as fallback/code
models — but expect ~5–10 tok/s because part of the model runs on the CPU. For
interactive dashboard use, stay on `qwen3:14b` or `qwen3:30b-a3b`.

Pull the models you want (the default is required for AI analysis):

```bat
ollama pull qwen3:14b            :: default analyst model  (~9.3 GB, fits in VRAM)
ollama pull qwen3:30b-a3b        :: optional quality upgrade (MoE)
ollama pull deepseek-r1:32b      :: optional fallback / deep reasoning
ollama pull qwen2.5-coder:32b    :: optional code model
```

Change the defaults in `.env` (`OLLAMA_MODEL`, `OLLAMA_FALLBACK_MODEL`,
`OLLAMA_CODE_MODEL`) or pick any installed model per-request from the dashboard's
AI Analysis tab.

## Quickstart (Windows)

Prerequisites: **Python 3.12+** (with the `py` launcher), **[Ollama](https://ollama.com)**
installed, ~10 GB free disk for the default model.

```bat
:: 1. one-time setup: venv + dependencies + .env + database
scripts\setup.bat

:: 2. pull the default model (once)
ollama pull qwen3:14b

:: 3. start Ollama (if not running), the backend and the dashboard
scripts\start_all.bat
```

Then open **http://localhost:8501** (dashboard). The API and its interactive docs live at
**http://127.0.0.1:8000/docs**.

Individual components:

| Script                       | What it does                                                        |
|------------------------------|---------------------------------------------------------------------|
| `scripts\setup.bat`          | Creates `.venv`, installs `requirements.txt`, copies `.env.example` → `.env`, initialises the DB |
| `scripts\start_backend.bat`  | Runs `uvicorn backend.api.main:app` on `127.0.0.1:8000`             |
| `scripts\start_dashboard.bat`| Runs `streamlit run dashboard/app.py` on `localhost:8501`           |
| `scripts\start_all.bat`      | Checks/starts Ollama, then opens backend + dashboard in two windows |

## Docker setup

**Ollama stays on the host** — it needs direct GPU access, which is simplest outside a
container on Windows. The compose file only runs the backend and the dashboard and points
them at the host's Ollama via `host.docker.internal:11434`.

```bat
:: 1. make sure Ollama is running on the host and the model is pulled
ollama pull qwen3:14b

:: 2. build and start backend (:8000) + dashboard (:8501)
docker compose up --build
```

- Dashboard: http://localhost:8501 — Backend: http://localhost:8000/docs
- The SQLite DB is bind-mounted at `./data`, so Docker and native runs share the same cache
  and paper-trading account.
- `restart: unless-stopped` keeps both services up across reboots (until you `docker compose down`).

## Usage walkthrough

A typical research loop, entirely from the dashboard (or `curl` against the API):

**1. Fetch data** — sidebar: pick `binance` / `BTCUSDT` / `1h`, click **Fetch data**.

```bash
curl -X POST http://127.0.0.1:8000/api/data/fetch \
     -H "Content-Type: application/json" \
     -d '{"source":"binance","symbol":"BTCUSDT","timeframe":"1h","lookback_days":365}'
```

**2. Ask the AI analyst** — AI Analysis tab → pick a model → **Run analysis**.
The backend builds an indicator snapshot (RSI zone, MACD state, Bollinger position,
volatility, momentum, ...) and asks the local LLM for structured JSON.

```bash
curl -X POST http://127.0.0.1:8000/api/analysis \
     -H "Content-Type: application/json" \
     -d '{"source":"binance","symbol":"BTCUSDT","timeframe":"1h"}'
# → {"sentiment":"bullish","confidence":62,"risk_commentary":"...","key_indicators":[...],...}
```

**3. Backtest a strategy** — Backtest tab → choose `trend_following` (or any of the 5) →
run. You get an equity curve, the full metrics table and every simulated trade. Validate
robustness with the **walk-forward** section (out-of-sample folds).

```bash
curl -X POST http://127.0.0.1:8000/api/backtest \
     -H "Content-Type: application/json" \
     -d '{"source":"binance","symbol":"BTCUSDT","timeframe":"1h","strategy":"ensemble","limit":2000}'
```

**4. Paper trade it** — Paper Trading tab → submit an order (leave qty empty for
ATR-risk-based auto-sizing, optionally set SL/TP), then click **Tick** to process the
latest candle: pending limits/stops fill if touched, SL/TP are enforced, equity is
snapshotted. The risk manager blocks orders that violate the rules below.

```bash
curl -X POST http://127.0.0.1:8000/api/paper/orders \
     -H "Content-Type: application/json" \
     -d '{"symbol":"BTCUSDT","side":"buy","order_type":"market"}'
curl -X POST http://127.0.0.1:8000/api/paper/tick \
     -H "Content-Type: application/json" \
     -d '{"symbol":"BTCUSDT","refresh":true}'
```

**5. Compare strategies** — Strategy Comparison tab runs all 5 strategies on the same
data and charts their metrics side by side.

## API reference

Interactive docs: `http://127.0.0.1:8000/docs`. All bodies are JSON; all timestamps are
ISO-8601 UTC.

| Method | Path                              | Body / query                                                             | Returns |
|--------|-----------------------------------|--------------------------------------------------------------------------|---------|
| GET    | `/health`                         | —                                                                        | `{"status":"ok","ollama_available":bool,"db":"ok","paper_only":true}` |

| GET    | `/api/data/ohlcv`                 | `?source&symbol&timeframe&limit=500&features=false`                      | candle records (`features=true` adds indicator columns) |
| GET    | `/api/data/cached`                | —                                                                        | `{"items":[{source,symbol,timeframe,rows,first_ts,last_ts}]}` |
| POST   | `/api/analysis`                   | `{source,symbol,timeframe,model?}`                                       | `MarketAnalysis` JSON (sentiment, confidence, ...) |

## Risk-management rules (paper account)

Enforced by `backend/paper_trading/risk.py` on every order; identical cost model in the
backtester. All values are `.env`-configurable.

| Rule                | Default                                            | Setting |
|---------------------|----------------------------------------------------|---------|
| Per-trade risk      | 1% of equity                                       | `RISK_PER_TRADE` |
| Position sizing     | `(equity × risk) / (2 × ATR14)`, notional capped at 95% of equity | `RISK_PER_TRADE`, `ATR_STOP_MULTIPLIER` |
| Stop-loss           | entry ∓ **2 × ATR14**                              | `ATR_STOP_MULTIPLIER` |
| Take-profit         | entry ± **3 × ATR14**                              | `ATR_TAKE_PROFIT_MULTIPLIER` |
| Max open positions  | 5 — 6th order rejected                             | `MAX_OPEN_POSITIONS` |
| Daily loss limit    | −3% day PnL → new entries halted for the day       | `DAILY_LOSS_LIMIT` |
| Circuit breaker     | 10% drawdown from peak equity → **all** trading halted until manual reset (`POST /api/paper/reset`) | `CIRCUIT_BREAKER_DRAWDOWN` |
| Commission          | 0.1% of notional per fill                          | `COMMISSION_RATE` |
| Slippage            | 0.05% adverse on market/stop fills                 | `SLIPPAGE_RATE` |
| Starting capital    | $100,000 (simulated)                               | `INITIAL_CAPITAL` |

## Troubleshooting

| Symptom | Cause & fix |
|---------|-------------|
| `/health` shows `"ollama_available": false`; AI Analysis errors with 502 | Ollama is not running. Start the Ollama app (`"%LOCALAPPDATA%\Programs\Ollama\ollama app.exe"` or `ollama serve`), verify with `curl http://localhost:11434/api/version`. `scripts\start_all.bat` does this check for you. |
| Analysis fails with model errors; `GET /api/models` shows the default missing from `installed` | The model isn't pulled. Run `ollama pull qwen3:14b` (and optionally the fallback `deepseek-r1:32b`). |
| AI answers are extremely slow (~5–10 tok/s) | You're on a 32B **dense** model that CPU-offloads on a 16 GB GPU. Switch `OLLAMA_MODEL` to `qwen3:14b` (fits in VRAM) or `qwen3:30b-a3b` (MoE). Check with `ollama ps` — look at the CPU/GPU split. |
| Yahoo returns few/no intraday rows despite a large `lookback_days` | Yahoo limits intraday history (roughly: `1m` ≈ last 7–8 days, other intraday ≤ 60–730 days depending on interval). The fetcher clamps the window and logs a warning — use `1d` for long histories, or Binance/Bybit for deep intraday crypto data. |
| First candle request is slow or empty | Nothing cached yet. `POST /api/data/fetch` (or the sidebar Fetch button) first; the background scheduler keeps cached series updated every 15 minutes afterwards. |
| Orders rejected with a risk reason | Working as intended: max positions / daily loss / circuit breaker (see table above). A tripped circuit breaker requires `POST /api/paper/reset` — this wipes the paper account. |
| Port 8000/8501 already in use | Stop the other process or change `API_PORT` in `.env` (and `API_URL` for the dashboard) / Streamlit's `--server.port`. |
| Docker: backend can't reach Ollama | Ollama must run on the **host**, not in a container. Compose already sets `OLLAMA_URL=http://host.docker.internal:11434` + `extra_hosts: host-gateway`. On Windows also set Ollama to listen beyond localhost if needed: `setx OLLAMA_HOST 0.0.0.0` then restart Ollama. |
| `scripts\setup.bat` fails at "py not found" | Install Python 3.12+ from python.org with the "py launcher" option enabled, then rerun. |
